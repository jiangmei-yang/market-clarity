# ADR-0003：决策验证采用可追溯证据状态

- 状态：Accepted
- 日期：2026-07-29
- 负责人：项目团队

## 背景

当前公告核实主要使用标题关键词。标题相关不代表原说法中的主体、金额、时间和因果关系全部成立；“未找到”也不能解释为事件已被证伪。若 AI 直接生成综合意见，用户容易把整理结果误解为投资建议。

## 决定

Decision Validation 必须建立：

```text
原子说法 → 所需证据 → 证据项 → 核实状态 → 对原判断的影响
```

统一使用以下状态：

- `supported`
- `partially_supported`
- `contradicted`
- `insufficient`
- `unavailable`
- `stale`

每条肯定结论必须引用来源、日期、链接或 evidence ID，并显示检索覆盖。标题命中只用于候选召回，不能单独产生 `supported`。“未找到”只能进入 `insufficient`，除非高等级正式证据明确冲突，才可进入 `contradicted`。

AI 输出限定为已确认、未确认、对原判断的逻辑影响和下一步核实问题，不得输出买卖建议。

## 原因

- 让结论可以审计和重复验证；
- 防止二手资料和关键词命中被过度解释；
- 让失败、过期和证据不足成为一等状态；
- 保持产品“帮助检查，不替用户决定”的定位。

## 影响

- Python 与 TypeScript 需要共享状态语义；
- 决策记录需保存当时证据快照；
- UI 应逐条展示说法，而不是给整笔交易一个综合分数；
- 评估必须覆盖部分支持、冲突、无结果、过期、不可用和提示注入；
- 旧字段需要兼容或迁移说明。

## 备选方案

- 继续只做标题关键词匹配：召回简单，但不足以支持事实结论；
- 使用单一真假标签：无法表达覆盖限制和部分支持；
- 让模型直接综合打分：难以审计，并容易被理解为投资建议。
