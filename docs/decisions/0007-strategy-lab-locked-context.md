# ADR-0007：锁定历史按完整研究上下文封存

- 状态：Accepted
- 日期：2026-07-31
- 负责人：Codex

## 背景

策略研究室原先只按“股票样本 + 数据指纹 + 锁定名额”封存锁定历史。只要某个策略在一个样本上打开过锁定区，同一数据截止日下的其他规则、目标和成本设置都会被拒绝。结果是完成一次研究后，用户即使明确创建了另一项新研究，也无法再运行回测。

与此同时，策略名称、白话描述和随机 DSL ID 会改变 confirmation hash，但不会改变实际计算条件。相同经济规则因此可能无法命中旧哈希复用，又被宽泛的封存记录拒绝。

## 决定

锁定历史改为按完整、可计算的研究上下文封存：

- 股票样本和数据指纹；
- 因子、过滤、组合、调仓和成本；
- 研究目标与固定参照口径；
- 引擎和方法版本；
- 锁定检查名额。

策略名称、白话描述、随机 ID、创建时间和界面状态不进入该上下文。

同一完整上下文再次运行时，优先按 `run_context_key` 或已存运行的规范化上下文复用历史结果，不重新计算或再次打开锁定区。实际规则、目标、成本或样本发生变化时，视为一项新的、仍受候选预算和单次锁定规则约束的研究。

## 原因

- 保持同一研究不可在看过锁定结果后继续调参；
- 允许用户开展另一项明确确认、边界固定的新研究；
- 让改名或随机 ID 不再造成“既不能复用、也不能运行”；
- 继续记录每次研究的 confirmation hash、上下文键和数据版本，保留审计能力。

## 影响

- 旧版仅按样本封存的记录不再阻断所有新策略；新运行会写入完整上下文封存键。
- 相同计算上下文的结果仍然幂等复用，前端会明确显示没有重复计算。
- 不改变 DSL 白名单、候选预算、验证区通过线、锁定区只打开一次或禁止实盘交易等边界。
- 用户仍可能主动创建多个不同研究问题；产品不得把多次历史研究包装成未来预测或买卖信号。

## 备选方案

- 继续按整个样本封存：安全最保守，但完成一次研究后页面几乎不可继续使用。
- 仅按 confirmation hash 封存：会把改名和随机 ID 当作新研究，无法阻止相同计算规则重复窥视。
- 删除锁定机制：会破坏验证设计，不采用。
